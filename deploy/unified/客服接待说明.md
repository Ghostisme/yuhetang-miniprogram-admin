# 客服接待与微信官方工具

本后台的会话生命周期是：新咨询待接入 → 员工点击接入 → 当前接待人回复 → 结束后历史只读。另一员工不能直接越过接待人回复，交接需先退回待接入。新消息有未读提示，可在后台开启桌面通知并授予浏览器通知权限。

这些状态在本后台与小程序“在线咨询”之间通过业务接口同步；微信原生客服消息通过签名/加密回调接收，并由客服发送接口回复。

小程序原生客服的开放接口没有给本系统提供微信官方客服工具接待队列的双向状态控制。官方文档说明：开发者可在客户消息的响应中返回 `transfer_customer_service`，将当次消息交给网页版客服；一旦客服在官方工具接入，接待期间的新消息会直接交给官方工具，直到客服关闭会话，或超过文档规定的 30 分钟后恢复开发者推送。等待队列中的消息仍可推送给开发者。

当前 Java 回调确认消息后返回 `success`，未主动转发到官方工具。官方工具曾接入的会话及其人员资格仍由微信管理；在本后台点击“结束”不能代表微信官方工具中的会话也已经关闭，官方工具中的回复也不能假定会自动归档到本后台。

如果以本后台为统一接待入口，操作顺序为：

1. 在微信官方客服工具结束已有会话，停止在该工具继续接入客户。
2. 保持小程序消息推送到现有 Java 回调，使用未绑定为客服的客户微信发一条新消息。
3. 确认本后台显示该新消息及“待接入”，点击接入后再回复一次，并在客户手机核实。
4. 结束后核对历史只读；客户实际发送新消息后产生新待接入会话。

如业务要求两个工作台同时接待并同步队列、接待人和结束状态，需要提供相应状态接口的另一客服平台接入方案；不能用本系统数据库中的状态冒充已经改变了微信官方工具的状态。
